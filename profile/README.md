<p>关于「自动化交付」的提问，几乎都集中在五个时间点上：下单后多久能用、交付的到底是什么、环境谁配、连不上找谁、什么时候该加量。这五个问题按落地顺序排下来，恰好是一条完整的交付链。这篇就按这个顺序答，每个问题给出可验证的判据，而不是笼统地说「当天可用」「专人跟进」——这两句话在真正落地时需要被翻译成具体的检查动作。</p>

<h2>一、问题一：从下单到能跑通，当天真能做到吗</h2>
<p>「当天可交付」通常成立，但「当天能跑通」取决于你这一侧的准备程度，两件事不是一回事。</p>
<h3>交付时间的两段构成</h3>
<p>第一段是对方开通，拿到地址、端口与鉴权信息，多数在几小时内；第二段是你这边配置并验证，快的一小时，慢的半天。宣传里的「当天」通常指第一段，第二段要靠自己压。想当天跑通，最好在付款前就把客户端和环境准备好。</p>
<h3>下单前该准备好的三样</h3>
<p>一是要接入的账号清单与它们的地区归属，决定要哪个城市的段；二是客户端的配置文件路径，避免拿到信息后现找；三是验收脚本或检查清单，拿到出口就能立刻测。三样齐了，当天跑通是常态。</p>
<p>有两种情况会拖到第二天：需要特定城市或特定运营商、需要报备来源 IP、以及跨时区沟通。这三种情况建议提前一天下单，别卡在业务节点上。</p>

<h2>二、问题二：所谓自营家宽出口，交付的是什么</h2>
<p>这个词被用得很松，实际要问清的是三件事：地址归属、上游形态、以及是否独享。</p>
<h3>地址归属看 ASN</h3>
<p>交付后第一件事是查 <code>https://ipinfo.io/json</code>，看 <code>org</code> 字段是不是当地家宽运营商、<code>type</code> 是不是 residential。这是少数能自己验证的硬指标，其他描述都是话术。</p>
<h3>独享要看分配记录</h3>
<p>「自营」不等于「独享」。要问的是这条地址近 30 天被多少个账号使用过。正规方案能给出分配记录，给不出的只能靠自测：连续三天记录出口与 ASN，看是否稳定在同一段。</p>
<h3>交付清单应该包含什么</h3>
<p>地址与端口、鉴权方式（口令或白名单）、带宽上限、可用时段、以及一份能照着做的配置说明。少任何一项，落地时都要多一轮沟通。下面这张表可以用来核对交付是否完整。</p>

<h2>三、问题三：一号一环境，是交付方配还是自己配</h2>
<img src="/tp.png" alt="Claude住宅IP自动化交付后一号一环境配置核对">
<p>多数情况下交付方给的是「通道」，环境要自己配。把这件事想清楚，能避免到手后无人可用。</p>
<h3>交付方通常负责到哪一步</h3>
<p>到「这条地址能连、能出网」为止。浏览器配置、时区语言、账号登录，属于账号运营侧，极少包含在交付里。少数方案提供环境配置服务，但要额外收费且需要提供账号信息，涉及安全边界，签之前想清楚。</p>
<h3>自己配的最小工作量</h3>
<p>一个账号一份浏览器配置、一条固定出口、时区与语言跟随出口城市，做完大约十分钟一个。十个号两小时内能完成，前提是提前把模板做好，之后复制改参数即可。</p>
<p>配好之后留一份记录，这一步别省：账号、环境目录、出口地址、配置时间四项记一行。这份记录的价值在换人接手和出问题复盘时才体现，务必在配置当天就写，别指望事后回忆。</p>

<h2>四、问题四：连不上了找谁，报障要带什么</h2>
<p>「由卖家直接跟进」这句承诺，落地时取决于你报障的信息是否完整。信息散着给，来回就是几轮。</p>
<h3>报障三件套</h3>
<p>出现时间（精确到分钟）、当时的出口地址与检测页截图、失败请求的返回码。三样齐了，对方能直接判断是线路、鉴权还是账号侧问题，不用先反问一轮。</p>
<h3>先自己排除两种情况</h3>
<p>一是本地网络问题，换一个网络环境试同一出口；二是鉴权过期，检查口令是否被改、来源 IP 是否变动（动态 IP 重启光猫就会变）。这两种占实际报障量的相当一部分，自己先排除能省很多时间。</p>
<h3>什么指标说明该换而不是修</h3>
<p>同一地址 24 小时内三次以上失败、地址类型从 residential 变成 hosting、或同段多个账号同时异常，满足任一条就申请更换。反复修一条已经劣化的线路，成本比换一条高。</p>

<h2>五、问题五：什么时候该加量，什么时候该换方案</h2>
<p>自动化跑顺之后，这两个判断会反复出现，给几条可量化的信号。</p>
<h3>该加量的信号</h3>
<p>任务排队时间持续超过十分钟、单条出口的并发长期贴着上限、新增账号找不到干净的同城段。三条出现一条，说明当前容量或地址库存已经不够，加量比调优更有效。</p>
<h3>该换方案的信号</h3>
<p>失败率连续两周高于百分之三且换地址无改善、换新响应时间超过一天、地址类型多次不符。这类问题不是加量能解决的，属于供给质量问题，换方案比继续投入划算。</p>
<p>加量时有两条纪律：新号永远加在新段上，不要塞进已经养好的段；一次只扩一组，扩完观察一周再动下一组。这两条能避免「越扩越乱」，也是自动化跑量的前提。</p>

<h2>常见问答</h2>
<h3>当天交付是不是保证当天能用？</h3>
<p>答：不是保证，是常态。开通通常在几小时内完成，能否当天跑通取决于你这边的配置与验证是否就绪。需要特定城市或需要报备 IP 的，建议提前一天安排。</p>
<h3>自营家宽出口和普通住宅 IP 有什么区别？</h3>
<p>答：前者强调地址归属与上游形态，ASN 直接属于当地 ISP；后者是一个更宽泛的说法，可能包含转售段。区别要靠 ASN 与分配记录验证，不能只看名称。</p>
<h3>环境配置能不能让对方代做？</h3>
<p>答：少数方案提供，但通常需要交出账号信息，安全边界会变模糊。更稳妥的做法是自己按模板配，把配置说明当作验收项，让对方把文档写清楚。</p>
<h3>连不上时最常被忽略的原因是什么？</h3>
<p>答：来源 IP 变动。很多方案用白名单鉴权，办公室宽带重启光猫后公网 IP 变了，白名单立刻失效，表现就是「昨天还好今天连不上」。报障前先查一次自己的公网 IP。</p>
